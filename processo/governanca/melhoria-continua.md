# Melhoria contínua

O processo aprende com o uso (recomendação R6 da Sprint 5).

```
Painel de métricas  →  Retrospectiva do processo  →  Melhoria vira change  →  Nova versão do processo
     (AF11)                (AF12, a cada release)       (PR neste portal)          (changelog)
        ↑                                                                               │
        └───────────────────────────────────────────────────────────────────────────────┘
```

## Como propor uma melhoria

1. Qualquer pessoa abre um PR no repositório do processo com a alteração proposta.
2. O PR descreve o problema, a evidência (métrica ou caso real) e a mudança.
3. O Comitê do Processo revisa e aprova.
4. O changelog é atualizado e a versão do processo sobe.

Os números e as lições de cada release ficam no [histórico organizacional](/docs/governanca/historico-organizacional).

Atividades detalhadas: [Contínuo · Melhoria do processo](/docs/fases/melhoria-continua).
